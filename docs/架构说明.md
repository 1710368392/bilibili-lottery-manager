## 二、数据契约

### GM 存储键（9 个，改数据结构时必须同步考虑兼容性）

| 键 | 内容 |
|---|---|
| `bili_lottery_ledger_v1` | **台账主体**，主键是 `dynId` |
| `bili_lottery_trash_v1` | 回收站（删除的记录归档，平时不加载）|
| `bili_lottery_settings_v1` | 设置（对应 `CONFIG`）|
| `bili_lottery_unfollowed_v1` | 已取关记录 `{upMid: 时间戳}` |
| `bili_lottery_win_notified_v1` | 中奖通知去重（10 分钟窗口，跨标签）|
| `bili_lottery_pages_v1` | 多标签页心跳 |
| `bili_lottery_fab_pos_v1` | 票根位置 `{mode,edge,left,top}` |
| `bili_lottery_ui_v1` | UI 偏好 |
| `bili_lottery_panel_pos_v1` | 面板位置 |

### 台账记录字段（`ensureItem`，L6540）

```js
{
  dynId, origId, upMid, upName, pubTs,   // 身份与来源
  text,            // 正文（截断 120 字）
  dynType,         // 1=转发 2=图文 4=文字 8=视频 64=专栏 …
  source,          // 'api' = 数据来自官方接口
  drawTs,          // 开奖时间戳
  drawUnknown,     // 用户确认「文案没写日期」
  won,             // true=中奖 / false=未中 / null=结果未定
  official,        // true=官方抽奖 / false=自发 / null=待判定
  forLotteryFollow,// 是否为抽奖关注
  deleted, winningsConfirmed, prizes, participants, noSync, createdAt
}
```

**关键字段语义**：

- `official: null` 是「待确认」，不是「未知」—— 删除时受 `allowCheckUnverified` 开关约束
- `dynType` 用数字，`DYN_TYPE_MAP` 负责在字符串（`DYNAMIC_TYPE_FORWARD`）与数字之间转换

### 状态机（`computeStatus`，L374）

| key | 标签 | 可删 |
|---|---|---|
| `won` | 已中奖 | ❌ 永锁 |
| `pending` | 未开奖 | ❌ 永锁 |
| `unknown` | 开奖日期不明 | 看 `allowCheckUnverified` |
| `needcheck` | 结果存疑 | 看 `allowCheckUnverified` |
| `cooldown` | 缓冲期 | ❌ 过了缓冲期才进下一档 |
| `safe` | 建议删除 | ✅ |
| `deleted` | 已删除 | — |

## 三、B 站接口（全部走 `GM_xmlhttpRequest`，需在 `@connect` 声明域名）

| 接口 | 用途 |
|---|---|
| `api.bilibili.com/x/polymer/web-dynamic/v1/feed/space` | 读自己的动态流（扫描建档、浮条拉最新），两个变体（带/不带 `host_mid`）|
| `api.bilibili.com/x/dynamic/feed/operate/remove` | 删除动态 |
| `api.vc.bilibili.com/dynamic_svr/v1/dynamic_svr/rm_dynamic` | 删除动态（旧接口，备用/降级）|
| `api.bilibili.com/x/relation/modify` | 取关 / 关注 |
| `api.bilibili.com/x/relation/followings` | 关注列表 |
| `api.vc.bilibili.com/lottery_svr/**/lottery_notice` | **官方抽奖数据**（开奖时间/奖品/中奖名单）。代码里 v1 与 v2 都有，按可用性降级 |

另有动态详情接口 `/x/polymer/web-dynamic/v1/detail`（按需拼接）。

官方抽奖数据是判定「已开奖 / 中奖 / 建议删除」的权威来源。
新增接口时记得同步 `@connect` 声明（当前只有 `api.bilibili.com` 与 `api.vc.bilibili.com`）。

## 四、转发浮条链路（最脆弱的一环）

```
B站转发请求
  → hookRepost() 改写 unsafeWindow 的 XHR.send / fetch
  → isRepostTrigger(url) 判定是否转发请求
  → handleRepostSuccess() 等 1.5s（等动态流刷出）
  → 拉 space feed 取最新一条
  → 三重过滤：5 分钟窗口 + 同条去重 + 类型/文案判定
  → showFloat() 建浮条
```

### 三个高频故障点

**① hook 必须改 `unsafeWindow`**，不是沙箱的 `window`
脚本声明了 `@grant` → Tampermonkey 在沙箱运行，改沙箱对象页面感知不到。L6833：
```js
const W = (typeof unsafeWindow !== 'undefined' && unsafeWindow) ? unsafeWindow : window;
```

**② 接口判定正则可能失效**
```js
const REPOST_URL_RE = /\/x\/dynamic\/(feed|opus)\/(create|repost)|dynamic_repost|\/x\/dynamic\/feed\/create/;
```
2026-10-18 实测 B 站现行接口 `x/dynamic/feed/create/dyn` 命中。若 B 站改路径，hook 会静默失效。

**③ 浮条建了但看不见** ← 2026-10-18 真实踩坑
`.blm-fl-in` 漏了 `display:block`，元素永远停在 `display:none`。详见 `AGENTS.md` 铁律 2。

### 排查工具
油猴菜单「**转发监听诊断**」输出全链路日志；「**试弹一条测试浮条**」一秒区分「显示坏了」还是「上游没识别」。

## 五、测试架构

`test-smoke.js`（约 268 KB，组号至 [87]，1047 条断言）：

1. **整体 eval 脚本**：`eval(src)` 跑完整个 IIFE，在 `console.log('[抽奖动态管理器] 已启动')` 之前插一行
   `globalThis.__T__ = {…}` 把内部函数暴露到 `globalThis`
2. **mock 浏览器**：`document` / `window` / `XMLHttpRequest` / `GM_*` 全是桩
   - `getElementById` 惰性创建元素并缓存（所以设置页控件永远拿得到）
   - `body` 需要 `dataset`（showFloat 会写 `el.dataset.fid`）和能返回非 null 的 `querySelector`
3. **两种断言**：
   - **行为断言**：直接调 `__T__` 里的函数验证输出（如 `computeStatus` 各状态）
   - **静态断言**：正则匹配 `src` 里的源码文本（如「显隐必须成对」「字段表 id 同源」）

**新加功能时的标准做法**：在末尾追加 `[NN]` 组，同时加行为断言（功能正确）和静态断言（防退化）。
静态断言特别适合锁住「显隐成对」「hover 不改布局」这类容易反复踩的规矩。

## 六、UI 体系

### 主题 token

CSS 变量定义在 **两处**，亮/暗各一套，作用域选择器必须包含所有挂 body 的浮层：

```css
#blm-panel,#blm-fab,.blm-float,#blm-detailbox,#blm-diag,#blm-stmenu,#blm-prizebox,#blm-trashbox{ … }
```

⚠️ **新增挂 body 的弹窗时必须加进这两行选择器**（亮 + 暗各一次），
否则 `background:var(--blm-bg)` 取不到值 → 整个弹窗透明。踩过两次（2026-10-10、2026-10-11）。

主要 token：`--blm-bg/bg2/bg3`、`--blm-text/text2/text3`、`--blm-border`、`--blm-primary`
（亮色琥珀 #D98E3B / 暗色香芋紫 #B890DC）、`--blm-danger`、`--blm-ok-*`、`--blm-warn-*`。

### 交互反馈语言（贯穿全项目的规矩）

- **hover 只改颜色 / 底色 / transform，绝不改布局**
  改布局会引起重排 → 元素从鼠标下移走 → 再次触发 hover → **死循环**
  （2026-10-17 书签圆点那次真实踩过：展开→位移→移开→收起→复位→再展开，无限抽搐）
- 想要展开效果就用**浮层遮挡**（absolute + z-index + 实底 + 柔影），不要推移兄弟元素
- 时长/缓动用变量：`--blm-dur-micro/state/enter/exit/spring`、`--blm-ease-enter/exit/spring/std`
- 所有动画都要在 `@media (prefers-reduced-motion: reduce)` 下关掉

### 票根唤起按钮（FAB）

26×78 竖版票根，两侧半圆打孔用 CSS `mask` 实现。
⚠️ **坑**：`mask` 会把元素自己的 `box-shadow` 一起裁掉 → 票根变平。
解法：外层套 `#blm-fab-wrap`，阴影用 `filter:drop-shadow()` 走打孔轮廓。
⚠️ 角标必须放在 `wrap` 里（不能放按钮内，会被 mask 裁）。
⚠️ **显隐同样适用铁律 2**。

### 层级

| 元素 | z-index |
|---|---|
| `#blm-fab-wrap` | 2147483000 |

| `.blm-float` | 2147483002（`bringFloatToFront` 递增到 2147483010）|

## 七、添加新功能的检查清单

### 加一个设置项

四处必须同步（漏一处就静默失效）：

1. `CONFIG`（L39）加默认值
2. `SET_FIELDS`（L5261）加 `['key', 's-key', 'type']`
3. `saveSettingsNow()`（L5318）加读取逻辑
4. 设置页渲染加控件（`srow()` 生成的 id 必须是 `s-<key>`）

有断言锁住 2 和 4 的 id 同源。

### 加一个页签内的 UI 元素

1. 用项目既有的类名体系（`.blm-btn` / `.blm-card` / `.blm-ckbox` / `.blm-tip` …）
2. 需要显隐 → 遵守铁律 2
3. 挂 body 的弹窗 → 加进 token 作用域两行
4. 改完想看效果 → 用 `tools/preview/` 的预览器，别直接刷新试错

### 改核心判断逻辑

第四部分（状态计算）和第五部分（猜日期）是整个脚本的大脑，改动前必读：
- 改 `computeStatus` → 必须同步改 `test-smoke.js` 的 `[3] 风险分级` 组
- 改 `guessDrawDate` → 必须同步改 `[2] 开奖日期识别` 组
- 涉及删除的改动 → 回头核对 `AGENTS.md` 六条红线
